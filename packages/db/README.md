# @workspace/db

Drizzle schema for the `mise` D1 database, its migrations, and the typed Reina de Espadas menu seed.

- `src/schema/`: one file per table. CHECK constraints derive from the `as const` enums in `@workspace/contracts`, so the database and the zod schemas accept the same values. Money is integer centavos, times are epoch ms, and business dates are `YYYY-MM-DD` in `America/Mexico_City`.
- `migrations/`: generated by `pnpm db:generate` (drizzle-kit). Never edit a migration that has been applied; generate a new one. `apps/api/wrangler.jsonc` points `migrations_dir` here.
- `src/seed/menu.ts`: the menu as typed data. `buildSeedRows` turns it into rows and `buildSeedStatements` into `INSERT … ON CONFLICT DO NOTHING` statements, which `pnpm db:seed:local` writes to `dist/seed.sql` and runs with `wrangler d1 execute`.

## Seed rules

- DiDi Food prices are placeholders equal to the counter prices (`is_placeholder = 1`) until the client sends the real list and the owner edits them (#15).
- Estimated costs are `NULL` (unknown) until the owner enters them (#15) or accepts a suggestion (#18).
- Re-running the seed inserts only missing rows and never overwrites the owner's edits.

## Tests

`pnpm --filter @workspace/db test` runs inside the Workers runtime (`@cloudflare/vitest-plugin`) against a local D1 with the migrations applied. Every test starts from empty tables.

## Better Auth tables

The Better Auth tables (`user`, `session`, `account`, `verification`, `rate_limit`, `passkey`) are generated by its CLI from the auth config, so they land as a follow-up migration with #5.
